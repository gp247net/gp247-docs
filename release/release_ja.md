# S-Cart のリリースとセキュリティ

## はじめに
このページは S-Cart（3.x 系）の**サイト運営者・管理者**向けです。サイトが安全かどうか、各リリースの新機能、更新方法がわかります。
最新リリース: **S-Cart 3.3.1**（2026-10-29）。

## サイトは安全ですか？
`php artisan gp247:info`（または `composer show "gp247/*"`）を実行し、各行を **安全な最低バージョン** の列と比べます。

| パッケージ | 安全な最低バージョン | 最新 |
| --- | --- | --- |
| gp247/core | **3.5.0** | 3.5.0 |
| gp247/front | **3.2.3** | 3.3.0 |
| gp247/shop | **3.3.1** | 3.3.1 |

- 「安全な最低バージョン」**より低い** → [すぐに更新してください](#更新方法)。
- **達している** → S-Cart を再インストールしていなくても、サイトは安全です。

> ⚠️ **注意:** セキュリティ修正を受けられるのは **3.x** 系のみです。2.x で稼働中のサイトは 3.x へ移行してください。
> **3 つのパッケージを同時に**更新してください: `gp247/shop` 3.3.1 には `gp247/core` 3.3 以上、`gp247/front` 3.2.3 には
> `gp247/core` 3.2.3 以上が必要です。

## 注目の新機能
- **管理画面のお問い合わせ受信箱** — お客様からのメッセージを管理画面でまとめて確認できます *(S-Cart 3.3)*
- **API 画面で REST API をオン／オフ** — 設定ファイルの編集は不要です *(S-Cart 3.3)*
- **ログイン試行回数の制限** — 管理画面のパスワードの総当たりを防ぎます *(S-Cart 3.3)*
- **送り状付きの標準配送** — 配送状況を注文画面で確認できます *(S-Cart 3.2)*
- **日本語と日本円** — 新規インストール時から利用できます *(S-Cart 3.2)*

## 更新方法
**手順 1 —** データベースとサイトのフォルダーをバックアップします。

**手順 2 —** コードを更新します。
```bash
composer update gp247/core gp247/front gp247/shop
```

**手順 3 —** データ・設定・キャッシュの更新を適用します。
```bash
php artisan gp247:update
```

**手順 4 —** `php artisan gp247:info` でバージョンを再確認します。

リリースによっては追加の対応が必要です。下記の各リリースの **📋 更新時の対応** をご覧ください。
詳しい手順は [GP247 の更新](https://gp247.net/ja/docs/system/how-to-update-gp247.html)をご覧ください。

### S-Cart 3.3.0 — 2026-10-28
**受信箱付きのお問い合わせフォームと、管理画面からの REST API のオン／オフ。**

**✨ 新機能**
- **管理画面のお問い合わせ受信箱** — お客様からのメッセージを管理画面でまとめて確認できます
- **REST API のオン／オフ** — API 管理画面で API と各バージョンを切り替え。設定ファイルの編集は不要です
  （[ドキュメント](../api/api-introduction_ja.md)）
- **ログイン試行回数の制限** — 管理画面のパスワードの総当たりを防ぎます
- **開発者向け:** 商品・注文・バナー・ページの REST API v2（フィルター、最終価格付き）。すべての API 応答にログ検索用のリクエスト ID

**🛡️ セキュリティ:** 5 件の修正 — [詳細を見る](#セキュリティ修正)。**すぐに更新してください。**

**🐞 不具合の修正:** SNS 共有画像（og:image）がページの画像と異なっていた。管理用の注文 API が 500 を返していた

**📋 更新時の対応**
- `php artisan gp247:update` を実行します — API キーをハッシュ化し、古いトークンに有効期限を設定します
- `GP247_API_LOGIN_THROTTLE` → `GP247_LOGIN_THROTTLE`、`GP247_API_LOGIN_IP_THROTTLE` → `GP247_LOGIN_IP_THROTTLE` に名前を
  変更します（旧名は読み込まれません）
- API を呼び出すアプリ: ログアウトは POST で行います（GET は廃止予定）。順次 API v2 へ移行してください

<sub>含まれるパッケージ: core 3.5.0 · front 3.3.0 · shop 3.3.1 · [GitHub Release](https://github.com/gp247net/s-cart/releases/tag/3.3.0)</sub>

問題の種類・影響範囲・修正済みリリースのみを記載し、悪用方法は記載しません。*（…のサイト）* と書かれた行は、その構成のサイトにのみ
影響します。括弧内の日付はパッケージの公開日で、`composer update` を実行したサイトはその日から安全です。

| 問題 | 影響範囲 | 修正済み |

| **総当たり攻撃、CSRF** | 管理画面のログイン試行回数に制限がなかった。ファイルマネージャーで他のサイトからファイルを変更できた | core 3.5.0 · shop 3.3.1 |

## サーバーソフトウェア（PHP・Web サーバー）
PHP と Web サーバーの不具合は GP247 のリリースではなく各提供元が修正します。こちらも最新の状態に保ってください。

| 問題 | 深刻度 | 修正済みの PHP |
| --- | --- | --- |
| **PHP2Shell** — リモートコード実行（CVE-2026-109618、CVE-2026-109619）· 2026-10-21 | 緊急 | 8.3.36 · 8.4.27 · 8.5.12 |

**対応方法**
- **PHP バージョンの確認:** `php -v`、または **管理画面 → サーバー情報**。
- **公式リリースの PHP**（php.net、公式 Docker イメージ、バージョンを選べる多くのコントロールパネル）: 使用中のブランチの
  修正済みバージョン以降に更新します。
- **Linux ディストリビューション（Ubuntu、Debian、RHEL など）やホスティング事業者が管理する PHP:** 古いバージョン番号のまま
  修正が適用されることが多く、**バージョン番号だけでは安全かどうか判断できません** — OS の最新アップデートを適用するか、
  CVE-2026-109618 と CVE-2026-109619 が修正済みか事業者に確認してください。
- **すぐに更新できない場合:** `php.ini` で `session.upload_progress.enabled = Off` を設定し（GP247 はこの機能を使いません）、
  PHP を再起動します。リスクは下がりますが、更新の代わりにはなりません。
- **Docker で運用している場合:** [DOCKER.md](https://github.com/gp247net/s-cart/blob/master/DOCKER.md) の「Security updates」に
  従ってください。
