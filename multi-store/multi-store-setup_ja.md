# Multi-Store — パート1: インストール

## はじめに
このドキュメントでは、稼働中の S-Cart の Web サイトに **Multi-Store** プラグインをインストールし、2つ目のストアを作成し、そのドメインを向け、購入済みであれば **Pro 版** を追加でインストールし、すべてが正しく動作することを確認する手順を説明します。基本的な技術知識のある Web サイトのオーナーや管理者の方を対象としています。手順どおりに進めれば動作し、プログラミングの知識は不要です。複数のストアの運用方法と各設定の意味は [パート2 — 運用](./multi-store-operations_ja.md) を参照してください。

## 始める前に必要なもの
- 稼働中の S-Cart **3.x** の Web サイト（`gp247/core` **3.0**、`gp247/shop` がインストール済み）。
- 同じ Web サイトにマルチベンダープラグインが **インストールされていない** こと — 2つのモデルは互いに排他的です。
- **新しいストアごとに1つのドメイン**、およびそのドメインをこの Web サイトに向けるための DNS と Web サーバー設定を変更する権限。
- サーバーで `php artisan` を実行する権限、**または** ステップ1の管理画面からのインストール方法を使うこと。

S-Cart の Web サイトがまだない場合は、[Multi-Vendor ドキュメントのパート1](../multi-vendor/multi-vendor-setup_ja.md) に従って先にプラットフォームをインストールし（S-Cart のインストール手順は同じです）、ここに戻ってきてください。

## ステップ1: Multi-Store プラグインをインストールする（無料版）
3つの方法から **1つ** を選びます。

**方法1 — GP247 ライブラリから（推奨）**
1. 管理画面にログイン →「拡張機能」→「プラグイン」(Plugins)。
2. 「ライブラリから」タブを開き、**MultiStore** を検索して「インストール」をクリックします。

**方法2 — zip ファイルのインポート**
1. 「拡張機能」→「プラグイン」→「インポート」タブを開きます。
2. プラグインの zip ファイルを選んでアップロードします。

**方法3 — 手動コピー（上の2つの方法でエラーになる場合）**
1. 解凍し、ソースコードのフォルダを `app/GP247/Plugins/MultiStore/` にコピーします。
2. プラグインの `public` フォルダを `public/GP247/Plugins/MultiStore/` にコピーします。
3. 「拡張機能」→「プラグイン」→「ローカル」タブを開き、**MultiStore** を探して「インストール」をクリックします。

Web サイトにマルチベンダープラグインがある場合、インストーラーは **その場で停止し、何も書き込みません** — これは意図した動作です。「条件と制約」のセクションを参照してください。

## ステップ2: 有効化する
1. プラグイン一覧で、MultiStore の行の「有効にする」をクリックします。管理画面のサイドバーに「マルチストア」メニューが表示され、次の項目が含まれます。
   - 「ストア一覧」 — 無料版のメイン画面。
   - *(Pro)* ラベル付きの4項目: 統合ダッシュボード、ストア管理者、商品の同期、商品別売上。
2. *(Pro)* の項目を1つクリックしてみてください。Pro 版がない場合は **機能の説明ページ** が開きます — これが正しい状態で、エラーではありません。

「マルチストア」→「ストア一覧」を開くと、既存のルートストア（ROOT）、上限の表示（例: *1/3 ストア*）、「ドメイン名の厳格チェック」(STRICT) のスイッチが表示されます。

## ステップ3: 2つ目のストアを作成する
1. 「マルチストア」→「ストア一覧」→「新規追加」を開きます。
2. **必須** の項目を入力します。

   | 項目 | ルール | 例 |
   | --- | --- | --- |
   | ストアコード | 一意、20文字以内 | `brandb` |
   | ドメイン | 一意、200文字以内、**`https://` を付けずに入力** | `brand-b.com` |
   | 言語 | 有効な言語の一覧から選択 | `English` |
   | 通貨 | 有効な通貨の一覧から選択 | `USD` |
   | テンプレート | インストール済みのテンプレートを選択 | `GP247Front` |
   | タイトル（言語ごと） | 必須、200文字以内 | `Brand B` |

   それ以外の項目は任意です: SEO キーワード（200文字以内）、説明（300文字以内）、ロゴ、電話番号、メールアドレス、住所、言語ごとの **メンテナンスページの内容**（サンプルが入力済みで、編集可能）。

3. 「保存」をクリックします。システムは、ストアとその初期データを1つのトランザクションで作成します — すべて成功するか、何も作成されないかのどちらかです。

上限（無料版: **ルートストアを含めて** 3ストア）に達している場合、新規追加ボタンはブロックされ、システムがはっきりと通知します — これは2つの版の境界で、エラーではありません。

## ステップ4: ドメインをシステムに向ける
新しいストアは、そのドメインが **実際にこの Web サイトに向いている** ときだけ開けます。S-Cart の外で行う作業は次のとおりです。

1. **DNS**: ドメイン（`A` レコードまたは `CNAME` レコード）を、Web サイトが稼働しているサーバーに向けます。
2. **Web サーバー**: そのドメインを同じ Web サイトに登録します — ルートドメインと同じ `public/` ルートフォルダです。Apache では `ServerAlias` を追加し、Nginx では `server_name` に追加します。コントロールパネル付きのホスティングでは、**同じフォルダを向く**「パークドメイン」/「アドオンドメイン」を追加します。
3. Web サイトが `https` で動いている場合は、新しいドメインに SSL 証明書をインストールします。

> 💡 **ヒント:** これは最も見落とされやすいステップです。管理画面でストアを作成していても、ドメインがシステムに向いていなければ、開くとドメイン業者のページや接続エラーになります — プラグインとは関係ありません。

## ステップ5: ドメインのチェックを有効にする（推奨）
「ストア一覧」で、「ドメイン名の厳格チェック」(STRICT) のスイッチをオンにします。

オンにすると、Web サイトはストアに登録したドメインと、`.env` のルートドメイン（`APP_URL`）**だけを表示** します。あなたのサーバーに向けられた未登録のドメインには、Web サイトの代わりに **アクセス拒否** ページが表示されます。これにより、他人が自分のドメインをあなたの Web サイトに向けることを防げます。

> ⚠️ **注意:** ドメインをすべて登録する **前に** STRICT をオンにすると、まだ登録していないストアから自分自身が締め出されます。ストアを作成してドメインを入力し終えてから、オンにしてください。

## ステップ6: 確認する
1. 新しいストアのドメインを開きます。ルートストアではなく、**そのストアのデザイン、言語、通貨** で Web サイトが表示されるはずです。
2. 管理画面で商品を作成（または編集）し、**新しいストアに割り当て** ます。その商品が新しいドメインに表示され、割り当てていなければルートストアには表示 **されない** ことを確認します。
3. 新しいストアでテスト注文をして、管理画面でその注文が正しいストアに記録されていることを確認します。
4. システムの状態を確認します。

   ```bash
   php artisan gp247:info
   php artisan gp247:doctor
   ```

## ステップ7（任意）: Pro 版を追加でインストールする
このステップは、Pro 版を購入済みの場合にのみ行います。Pro は無料版に **追加で** インストールするもので、置き換えるものではありません。

1. プラグイン一覧の **MultiStore** の行が、インストール済みかつ **有効** になっていることを確認します。Pro プラグインは無料版を必須の拡張機能として宣言しており、ない場合はインストールを拒否します。
2. ステップ1の3つの方法のいずれかで **MultiStorePro** をインストールします（通常は、GP247 から受け取った **zip ファイルのインポート**）。
3. 「有効にする」をクリックします。**インストールしただけで有効にしないと、Pro はまだ機能しません** — 「インストールしたのに説明ページが表示される」の最も多い原因です。
4. Pro のルートが登録されるよう、次のコマンドを実行します（または管理画面でキャッシュを削除します）。

   ```bash
   php artisan gp247:cache-rebuild
   ```

5. 管理画面を再読み込みし、ロックが解除されたことを示す3つのポイントを確認します。
   - 「マルチストア」メニューの4つの *(Pro)* 項目で、説明ページではなく **実際の画面** が開く。
   - 「ストア一覧」: 上限の表示が **無制限** に変わり、「ロック」列がクリックできる（以前は Pro ラベル付きで無効）。
   - 「ユーザー権限」→「ロール」に、ストア管理者に割り当てるための2つのサンプルロール **[M]Store Admin** と **[M]Store Member** が表示される。

何かを再インストールしたり、データを移行したりする必要はありません。ストア、商品、注文、設定はそのまま保持されます。

**Pro 版を無効化またはアンインストールした場合**: Pro の画面は説明ページに戻り、上限は3ストアに戻り、「ロック」列は無効になります。**データは削除されません** — 上限を超えたストアもそのまま残って動作し続け、商品同期のリンクやストア管理者の割り当ても保持されます。Pro を再インストールすれば、そのまま使い続けられます。

## 条件と制約（操作の前に確認）

**インストール時**
- **Web サイトにすでにマルチベンダープラグインがある場合、プラグインはインストールを拒否します** — 2つのプラグインは異なるモデルでストアのデータを共有するため、インストーラーは何かを書き込む前に停止します。先にもう一方のプラグインをアンインストールしてください。
- **`gp247/shop` がインストール済みである必要があります** — プラグインはショップの商品と注文に依存しています。
- **Pro 版には、有効な無料版が必要です** — Pro は拡張であり、置き換えではありません。
- **インストールしただけで有効にしないと機能しません** — どちらの版でも同じです。

**ストアの作成時**
- **ストアコードは一意で、20文字以内**。
- **ドメインは一意で、200文字以内** — システムはドメインそのものでストアを識別するため、2つのストアで同じドメインは使えません。
- **ドメインは `http://`/`https://` を付けず、末尾に `/` を付けずに入力します** — システムは自動で小文字に正規化しますが、`brand-b.com` の形式で正しく入力すると混乱を避けられます。
- **言語、通貨、テンプレート、タイトルは必須です** — どれか1つでも欠けると、ストアが正しく開きません。
- **無料版はルートストアを含めて3ストアまで** — ボタンを隠すだけでなく、サーバー側でチェックされます。

**稼働中のストアのドメインを変更する場合**
- **古いドメインではそのストアを開けなくなります** — Web サイトが実際に運用されていて Google にインデックスされている場合は、変更前に 301 リダイレクトを準備してください。
- **STRICT をオンにしたままドメインの登録を忘れると**、そのドメイン自体が拒否されます — すべて登録してからオンにしてください。

## トラブルシューティング
| 症状 | 対処方法 |
| --- | --- |
| 「マルチストア」メニューが表示されない | プラグインが（インストールだけでなく）**有効** になっているか確認し、`php artisan gp247:cache-rebuild` を実行します |
| *(Pro)* 項目で説明ページが表示されたまま | MultiStorePro が **有効** になっているか確認し、`php artisan gp247:cache-rebuild` を実行します |
| インストール時に競合エラーが表示される | Web サイトにマルチベンダープラグインがあります — 2つのモデルは排他的なため、先にもう一方のプラグインをアンインストールする必要があります |
| Pro のインストール時に拡張機能の不足が表示される | 先に無料の **MultiStore** プラグインをインストールして有効にします |
| 新しいドメインを開くと、ドメイン業者のページや接続エラーになる | DNS/Web サーバーでドメインがこの Web サイトに向いていません — ステップ4を参照してください |
| 新しいドメインを開くと **アクセス拒否** ページが表示される | STRICT がオンなのに、そのドメインがどのストアにも登録されていません。ストア設定の「ドメイン」欄を確認してください |
| 新しいドメインを開くと、ルートストアの内容が表示される | ストア設定のドメインが、実際に入力しているドメインと一致していません（`www` の有無、つづりの違い）。一致するように修正します |
| 新しいストアを追加できない | 無料版の上限（ルートを含めて3ストア）に達しています — Pro にアップグレードしてください |
| 画面に文字ではなく生のキーが表示される | 「ストア一覧」画面を一度開き直すか、プラグインを無効にしてから再度有効にします |
| 詳しいエラーを確認したい | `storage/logs/laravel.log` を開きます |

## よくある質問（Q&A）
**Q1: 2つ目のストアのために、ホスティングを追加で契約する必要がありますか？**

→ いいえ。すべてのストアは同じシステム、同じデータベースで動きます。**ドメイン** を追加して、この Web サイトに向けるだけです。

**Q2: ルートストア（ROOT）とは何ですか？**

→ S-Cart をインストールしたときからあるストアで、`.env` のドメインを使います。システム全体の土台なので、削除もロックもできません。

**Q3: 独自ドメインの代わりにサブドメイン（`b.brand-a.com`）を使えますか？**

→ はい。システムはリクエストのドメインと登録したドメインを比較するだけなので、同じ Web サイトに向いていれば、サブドメインも独自ドメインとまったく同じように動作します。

**Q4: STRICT のオンは必須ですか？**

→ 必須ではありませんが、ドメインをすべて登録したらオンにすることをおすすめします。他人が未登録のドメインをあなたの Web サイトに向けることを防げます。

**Q5: 無料版で3ストアを使っています。Pro をアンインストールすると、4つ目、5つ目のストアは消えますか？**

→ 消えません。ストアのデータは残り、動作し続けます。Pro を再インストールするまで、新しいストアを追加できなくなるだけです。

**Q6: Pro をインストールしたら、メニューを設定し直す必要がありますか？**

→ いいえ。*(Pro)* の項目は、もともと中継用のパスを指しています。Pro があれば、そのパスが自動で実際の画面に切り替わります。

**Q7: ストアを削除すると商品は消えますか？**

→ 商品、カテゴリ、バナー、コンテンツページは **削除されません** — そのストアとのリンクがなくなるだけです。ただし、注文、顧客、仕入先が残っているストアは **削除できません**。詳しくは [パート2 — 運用](./multi-store-operations_ja.md) を参照してください。
