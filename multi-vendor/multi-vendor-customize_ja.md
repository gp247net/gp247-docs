# Multi-Vendor — 第 3 部：カスタマイズ

## はじめに
このドキュメントでは、プラグインをアップデートできる状態を保ったまま、**Multi-Vendor マーケットプレイスをあなたのブランドに合わせる方法** を説明します。表示テキストとメール内容の変更、ストアページのデザイン変更、マーケットプレイスのスタッフの権限設定、そして開発者向けの原則です。対象はウェブサイトの管理者と開発者です。読み終えると、どこを変更してよいか、どう変更するか、そしてどこには絶対に触れるべきでないかがわかります。

全体を通しての原則：**プラグインフォルダー内のファイルは修正しないでください**。そこでの変更は、バージョンをアップデートすると失われます。以下の 3 つの正式な方法は、どれも **アップデートしても残ります**。

## 3 つのカスタマイズレベル

| レベル | できること | 必要なもの |
| --- | --- | --- |
| 1. テキストとメールの変更 | 画面のラベル、通知、メールの件名と本文のすべて | 管理画面に入るだけ |
| 2. デザインの変更 | ストアページ、ストア一覧、商品一覧、トップページのブロック | Blade ファイルの基本的な編集知識 |
| 3. コードによる拡張 | 他のプラグインの内容を挿入、価格ルールを追加 | 開発者 |

## レベル 1 — 表示テキストとメール内容の変更
プラグインのテキスト（画面のラベル、通知、**メールの件名と本文**）はすべて **データベースに保存された言語文字列** です。管理画面ですぐに修正でき、**ファイルの修正は不要** です。

1. **ローカライズ → 言語管理**（`/gp247_admin/language_manager`）を開きます。
2. **グループ** = `multi_vendor` で絞り込み、言語を選び、コードまたは画面に表示されているテキストで検索します。
3. 修正して **保存** します。すぐに反映され、**プラグインをアップデートしても残ります**。

すばやく探すためのコードの規則：

| コードのプレフィックス | 内容 |
| --- | --- |
| `multi_vendor.mail.*` | メールの件名と本文（例：`multi_vendor.mail.vendor_approved.subject`） |
| `multi_vendor.pro.*` | Pro 版の機能紹介ページのテキスト |
| その他 | 画面のラベル、ボタン、通知 |

初期値に戻したい場合：その行を削除してから **クイック設定画面を開き直してください** — プラグインが元の文字列を自動で再投入します。

> ⚠️ プラグインフォルダー内の言語ファイルは修正しないでください。これらはインストール時の通知にだけ使われ、**アップデート時に上書きされます**。

## レベル 2 — ストアページのデザイン変更

### トップページの「新着ベンダー」ブロック
このブロックは、プラグインのインストール時に、使用中のテンプレートの `blocks/` フォルダーにコピーされます。表示方法を変えるにはそこを直接修正し、ブロックの追加・削除は管理画面の **レイアウトブロック** で行います。

### ページ全体を独自のものに置き換える
その他のページは、プラグインに触れずに **独自のファイルに置き換え** られます。使用中のテンプレートに、次のパスで同じ名前のファイルを作成します。

```
app/GP247/Templates/<TemplateName>/Plugins/MultiVendor/<view-name>.blade.php
```

システムはテンプレートのファイルを優先し、ない場合にだけプラグインのファイルを使います。これにより、あなたの修正は **プラグインをアップデートしても失われません**。

置き換えられるページ：

| ビュー名 | 対応するページ |
| --- | --- |
| `vendor_index` | ストア一覧 `/shop` |
| `vendor_home` | ストアページ `/shop/{コード}` |
| `vendor_info` | ストアの **ストア情報** タブ |
| `vendor_product_list` | ストアページ内の商品一覧 |
| `hooks.order_dispute_box` | お客様の注文ページ下の申し立てボックス（Pro） |

**安全な方法**：プラグインの元のファイルの内容を上記のテンプレートのパスにコピーし、少しずつ修正します。こうすれば、ページに必要な変数を確実に残せます。

## マーケットプレイスのスタッフの権限設定
**マーケットプレイス** の画面は、S-Cart 共通の権限システムに含まれます。**ユーザー権限 → ロール / 権限** を開き、**画面の URL**（例：ストアの画面、支払いの画面）ごとに権限を付与します。権限のないスタッフには、該当するメニュー項目が表示されません。

これにより、役割ごとに仕事を割り振れます。審査担当者には承認待ちリストだけを、経理担当者には支払いの画面とレポートだけを表示できます。

> ベンダーアカウントはこの権限システムを **使いません** — 専用の `/vendor_admin` にログインし、常に自分のストアの範囲に制限されます。RBAC の詳細：[権限（Permission · Role · User）](../system/permission-and-role_ja.md)。

## レベル 3 — 開発者向け

- **プラグインフォルダー内のファイルは修正しないでください。** `app/GP247/Plugins/MultiVendor/` での変更は、アップデートすると失われます。3 つの正式な方法を使ってください：言語文字列（レベル 1）、テンプレートのビュー（レベル 2）、そして以下の拡張ポイントです。
- **お客様の注文ページに内容を挿入する**：プラグインは、ストアフロント共通のフックの仕組み（`gp247-config.front.plugin_hooks`、位置 `shop_order_detail_bottom`）に申し立てボックスを取り付けています。あなたの他のプラグインも、この仕組みを使って自分の内容を挿入できます。テンプレートの修正は不要です。
- **価格ルールを追加する**：ストアの顧客グループ別の価格（Pro）は、`gp247/shop` の価格シーム（`gp247-config.shop.price_resolvers`）に登録されます。そのため、商品ページ、カート、決済、クイック注文、見積書は常に同じ価格になります。他の価格プラグインも同じ形で追加登録できます。
- **コード内のストアの URL**：`/shop/...` を文字列で組み立てる代わりに、プラグインのヘルパーを使ってください。`.env` の変数を変えたときに、すべてのリンクが追従します。
- **安全なアップデート**：プラグインは、新規インストール、再インストール、アップデートのどの入口からでも、自動で状態をそろえます（メニュー、言語文字列、データテーブル）。ファイルを手動で置き換えたあとは、`php artisan gp247:cache-rebuild` を実行し、**クイック設定** 画面を一度開いてください。

あわせて読む：[プラグイン作成ガイド（v2 標準）](../extension/create-plugin_ja.md)、[テンプレート作成ガイド](../extension/create-template_ja.md)。

## 条件と制約（操作の前に確認）

**言語文字列を修正するとき**
- **管理画面で修正すればアップデート後も残りますが、プラグインフォルダー内のファイルを修正すると残りません** — プラグインの言語ファイルはアップデートのたびに上書きされます。
- **文字列の行を削除 = 初期値に戻す** ですが、プラグインが再投入するように、クイック設定画面を開き直す必要があります。そうしないと、画面にテキストではなく生のキーが表示されます。

**テンプレートのビューを置き換えるとき**
- **ファイル名は上の表のビュー名と完全に一致させてください** — 名前が違うと、システムはプラグインのファイルを使い続け、修正が反映されないように見えます。
- **ページに必要な変数を残してください** — 元のファイルをコピーして少しずつ修正し、ゼロから書き直さないでください。
- **使用中のテンプレートを変えると、修正は引き継がれません** — テンプレートごとに独自の上書き用フォルダーがあります。

**URL を変更するとき**
- 変更する前に [第 1 部 — インストール](./multi-vendor-setup_ja.md) の 4 つの注意点を確認してください：`public/` 内のフォルダーと重複させない、管理画面の URL と重複させない、古い URL は 404 になる。

**権限を設定するとき**
- **権限はメニュー名ではなく画面の URL ごとに付与します** — 表示名を変えても権限には影響しません。
- **ベンダーアカウントは管理者の権限システムに含まれません** — この方法でベンダーに管理者の権限を追加することはできません。

## よくある質問（Q&A）
**Q1: プラグインフォルダー内の Blade ファイルを修正するとどうなりますか？**

→ 修正はでき、すぐに反映されますが、**プラグインをアップデートすると失われます**。長く残すには、レベル 2 に従ってテンプレートのフォルダーにコピーしてください。

**Q2: ベンダーに送るメールの内容を変えたい場合、どこを修正しますか？**

→ **ローカライズ → 言語管理** で、グループ `multi_vendor` で絞り込み、`multi_vendor.mail.` で始まるコードを探します。ファイルの修正は不要です。

**Q3: 画面にテキストではなく生のキー（`multi_vendor.something` のようなもの）が表示されます。**

→ 言語文字列がまだ投入されていません。**クイック設定** 画面を一度開き直すか、プラグインをオフにしてから再びオンにしてください。

**Q4: ストアページのデザインを変えたあとでプラグインをアップデートすると、修正は失われますか？**

→ レベル 2 に従ってテンプレートのフォルダーにファイルを置いていれば、失われません。プラグインフォルダー内のファイルを直接修正した場合は、失われます。

**Q5: 経理スタッフには支払いの画面だけを見せたいのですが、できますか？**

→ できます。支払い/レポートの画面だけを含むロールを作成し、そのアカウントに割り当ててください。他のメニュー項目は表示されなくなります。

**Q6: ストアフロントのテンプレートを変えても、ストアページは動き続けますか？**

→ はい。新しいテンプレートに上書き用のファイルがなければ、システムはプラグインの初期デザインを使います。修正を残したい場合は、上書き用のフォルダーを新しいテンプレートにコピーしてください。
