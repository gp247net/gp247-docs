# Multi-Vendor — 第 1 部：インストール

## はじめに
このドキュメントでは、S-Cart 3.x のインストール、**Multi-Vendor** プラグイン（無料版）のインストールと有効化、購入済みの場合の **Pro 版** の追加インストール、最初のストアの作成、そしてマーケットプレイスが正しく動くかの確認までを説明します。対象は、基本的な技術知識のあるサイト運営者または管理者です。手順どおりに進めれば動かせます。プログラミングの知識は不要です。マーケットプレイスの運用方法と各設定の意味は [第 2 部 — 運用](./multi-vendor-operations_ja.md) をご覧ください。

## 始める前の要件
- PHP **8.3** 以上、Composer、MySQL/MariaDB（SQLite は簡単な試用向けのみ）。
- S-Cart **3.x**（`gp247/core` **3.0** と `gp247/shop` がインストール済み。プラグインはショップの商品、カート、注文を利用します）。
- 同じウェブサイトに Multi-Store プラグインが **インストールされていない** こと。2 つのモデルは同時に使えません。
- サーバー上で `php artisan` コマンドを実行できる権限があること。**または**、ステップ 2 の管理画面からのインストール方法を使います。

## ステップ 1：S-Cart 3.x をインストール
S-Cart 3.x のウェブサイトがすでに動いている場合は、このステップを飛ばしてください。

1. ウェブサイトを置きたいフォルダーで **ターミナル**（Windows では「コマンドプロンプト」）を開き、次の 2 行をそのまま入力して Enter を押します。

   ```bash
   composer create-project gp247/s-cart website-folder
   cd website-folder
   ```

   成功すると `website-folder` フォルダーができ、`.env` ファイルも自動で作成されます。

2. テキストエディターで `.env` ファイルを開き、データベース接続の部分をお使いの環境に合わせて修正します。

   ```env
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=s-cart
   DB_USERNAME=root
   DB_PASSWORD=
   ```

3. アプリケーションキーを作成します。

   ```bash
   php artisan key:generate
   ```

4. S-Cart を初期化します（テーブル、初期データ、管理者アカウントを作成）。

   ```bash
   php artisan gp247:install
   ```

   画面の質問に答えて進めます。成功すると、管理画面の URL とログイン情報が表示されます。必ず控えておいてください。

5. （任意）試用の商品があるように、ストアのサンプルデータを読み込みます。

   ```bash
   php artisan gp247:shop-sample
   ```

参考：[S-Cart の概要](https://gp247.net/en/s-cart/s-cart-overview.html)。

## ステップ 2：Multi-Vendor プラグイン（無料版）をインストール
次の 3 つの方法から **1 つ** を選びます。

**方法 1 — GP247 ライブラリから（おすすめ）**
1. 管理画面にログイン → **拡張機能** → **プラグイン**。
2. **ライブラリから** タブを開き、**MultiVendor** を探して **インストール** をクリックします。

**方法 2 — zip ファイルをインポート**
1. **拡張機能** → **プラグイン** → **インポート** タブを開きます。
2. プラグインの zip ファイルを選んでアップロードします。

**方法 3 — 手動でコピー（上の 2 つの方法でエラーになる場合）**
1. 解凍し、ソースコードのフォルダーを `app/GP247/Plugins/MultiVendor/` にコピーします。
2. プラグインの `public` フォルダーを `public/GP247/Plugins/MultiVendor/` にコピーします。
3. **拡張機能** → **プラグイン** → **ローカル** タブを開き、**MultiVendor** を探して **インストール** をクリックします。

成功すると、プラグインが一覧に表示され、**有効にする** ボタンが出ます。詳しくは [拡張機能のインストールガイド](https://gp247.net/en/user-guide-extension/guide-to-installing-the-extension.html) をご覧ください。

## ステップ 3：有効化とマーケットプレイスの設定
1. プラグイン一覧で、MultiVendor の行の **有効にする** をクリックします。管理画面のサイドバーに **マーケットプレイス** メニューが表示されます。
2. **マーケットプレイス** → **クイック設定** を開き、基本の値を設定します。
   - マーケットプレイスが差し引く **手数料率（%）**。
   - **ベンダー登録を許可** — ベンダーに自分で登録してもらう場合はオンにします。
   - **ベンダーを自動承認** / **商品を自動承認** — 手動で審査したい場合はオフにします。
3. **保存** をクリックします。各設定の詳しい意味は [第 2 部 — 運用](./multi-vendor-operations_ja.md) をご覧ください。

無料版を使っている場合、Pro 版のスイッチは **ロック** された状態で表示され、説明ページへのリンクが付きます。これは正しい状態で、エラーではありません。
ロックされたスイッチには、以前に保存した値ではなく **実際に動いている状態** が常に表示されます。サイトで以前 Pro 版を使っていてオフにした場合、それらの項目は **オフ** と表示され、
*ベンダーの注文操作* の項目は **配送ステータスのみ** と表示されます。無料版で実際に適用されるのはこの状態だからです。以前に保存した値は
**失われません**。Pro 版を再び有効にすれば、元の値に戻ります。

## ステップ 4：最初のストアを作成

**方法 A — 管理者が作成**
1. **マーケットプレイス** → **ベンダーストア** → **新規追加**：ストアコード（英数字のみ、最大 20 文字、例：`vendor01`）、名前、説明を入力 → **保存**。
2. **マーケットプレイス** → **ベンダーユーザー** → **新規追加**：メールアドレス、パスワードを入力し、作成したストアを選び、ステータスを **有効** にする → **保存**。
3. `https://your-domain/vendor_admin` を開き、上のメールアドレスとパスワードでログインします。成功すると、ストアのダッシュボードが表示されます。

**方法 B — ベンダーが自分で登録**（「ベンダー登録を許可」がオンの場合）
1. ベンダーが `https://your-domain/vendor_admin/register` を開き、情報とストアコードを入力します。
2. マーケットプレイスが「ベンダーを自動承認」をオフにしている場合、ストアは承認待ちになります。ベンダーがログインできるように、管理者が **ベンダーストア** でステータスを営業中にします。

**すぐに試せるサンプルデータ**（テスト用サイトでのみ使用）：

```bash
php artisan gp247:vendor-sample
```

このコマンドは、サンプルストア `vendor01`〜`vendor03` の 3 つを作成します。各ストアには、ログイン用アカウント 1 つ、仕入先 1 つ、独自のカテゴリ 3 つ、そして各カテゴリに 3 つずつ計 9 つの商品が用意されます。ストアページとカテゴリの絞り込みの両方で、表示する内容があります。

| ストアページ | ベンダーアカウント | パスワード |
| --- | --- | --- |
| `/shop/vendor01` | `vendor01@gp247.local` | `123456` |
| `/shop/vendor02` | `vendor02@gp247.local` | `123456` |
| `/shop/vendor03` | `vendor03@gp247.local` | `123456` |

3 ストアは無料版の上限とちょうど同じなので、サンプルデータはどちらの版でも使えます。コマンドを再実行すると、同じサンプルストアが置き換えられるだけで、増えることはありません。また、あなたが自分で作成したストアには触れません。**サイトを本番公開する前に、これらのアカウントを変更または削除してください。**

このコマンドは、ストアページに **レビュー** タブが用意されるよう、***Product Rating & Review* プラグインも自動で処理します**。プラグインがインストール済みならそのまま（オフならオンにするだけ）にし、
未インストールならインストールします。サイトにファイルがあればプラグインフォルダーから、なければプラグインストアからダウンロードします。サイトがインターネットに接続できない場合や、お使いの版で
ライセンスが必要な場合でも、コマンドは **サンプルデータの投入を最後まで完了** し、続けてインストールするためのコマンドを表示するだけです。他のプラグインにはまったく触れてほしくない場合：

```bash
php artisan gp247:vendor-sample --skip-rating
```

## ステップ 5：マーケットプレイスが正しく動くか確認
1. `https://your-domain/shop/vendor01` を開きます。ストアページに、そのベンダーのカテゴリと商品が表示されます（商品をまだ出品していなければ空です）。
2. `/vendor_admin` にログインし、商品を 1 つ作成します。マーケットプレイスで自動承認をオフにしている場合は、S-Cart の管理画面で承認します。
3. **最も重要なテスト**：異なる 2 つのストアの商品を 1 つのカートに入れて決済します。結果は **2 件の注文** になり、それぞれが 1 つのストアに属している必要があります。
4. システムの状態を確認します。

   ```bash
   php artisan gp247:info
   php artisan gp247:doctor
   ```

## ステップ 6（任意）：Pro 版を追加でインストール
Pro 版を購入した場合のみ、このステップを行います。Pro 版は無料版の **上に追加で** インストールするもので、無料版を置き換えるものではありません。

1. プラグイン一覧で **MultiVendor** の行が、インストール済みかつ **有効** になっていることを確認します。Pro プラグインは無料版を必須の拡張機能として宣言しており、無料版がないとインストールを拒否します。
2. ステップ 2 と同じ 3 つの方法のいずれかで **MultiVendorPro** をインストールします（通常は GP247 から受け取った zip ファイルを **インポート** します）。
3. **有効にする** をクリックします。**インストールしただけで有効にしていないと、Pro は機能しません**。「インストールしたのに説明ページが表示される」原因として最も多いのがこれです。
4. 次のコマンドを実行して（または管理画面でキャッシュを削除して）、Pro の URL を登録します。

   ```bash
   php artisan gp247:cache-rebuild
   ```

5. 管理画面を再読み込みし、ロックが解除されたことを 3 つの点で確認します。
   - **マーケットプレイス** メニュー → *(Pro)* が付いた項目をクリック：説明ページではなく **実際の画面** が開きます。
   - **クイック設定**：ロックされていたスイッチ（クイック注文、注文操作の範囲、本人確認、申し立て、追加のメール）が **変更できる** ようになります。
   - `/vendor_admin` でベンダーアカウントにログイン：サイドバーに Pro の項目（本人確認、マイプラン、新規注文、価格グループ、レビュー、ストアのプラグイン）が追加されます。

再インストールもデータ移行も不要です。ストア、ベンダーアカウント、注文、出金台帳はそのまま残ります。無料版を使っていたときに設定したストア個別の手数料率も、すぐに有効になります。

**必要な機能をオンにしてください** — Pro 版は、ベンダーの負担になるような機能を勝手にオンにしません。

| 設定 | オンにするとよい場合 | 初期値 |
| --- | --- | --- |
| クイック注文 | 代理店に卸売りしていて、お客様が一度に多くの行を注文する | オフ |
| ベンダーの注文操作 | ベンダーに注文の確認や完了を自分で行ってほしい | 確認 + 配送 |
| ベンダーの本人確認（KYC）を必須にする | 出店を許可する前、または支払う前に、ベンダーが誰かを把握する必要がある | オフ |
| 申し立て受付期間 / ベンダーの回答期限（日数） | お客様向けに申し立ての窓口を開く | 14 日 / 3 日 |
| 追加のメール | システムからベンダーとマーケットプレイスに自動で通知したい | オン |
| ベンダーによるプラグイン設定 | ベンダーに自分のストアの送料やプロモーションを設定してほしい | どのプラグインも開放しない |

**Pro 版をオフにしたりアンインストールしたりした場合**：Pro の画面は説明ページに戻り、Pro のスイッチは再びロックされます。ただし、**Pro 版が作成したデータは決して削除されません**。本人確認書類、申し立て、プランと契約期間、顧客の価格グループ、一括支払いのログはすべて残り、再インストールすればすべて表示されます。どちらの場合も無料版は通常どおり動き続けます。マーケットプレイスは止まらず、注文も失われません。

## URL のカスタマイズ（任意）
初期の URL を変更したい場合は、`.env` に次を追加してから `php artisan gp247:cache-rebuild` を実行します。

```env
MULTIVENDOR_FRONT_PATH=shop
MULTIVENDOR_ADMIN_PATH=vendor_admin
PREFIX_QUICK_ORDER_VENDOR=quick-order
PREFIX_CATEGORY_VENDOR=category-vendor
```

| 変数 | 変わる URL | 初期値 |
| --- | --- | --- |
| `MULTIVENDOR_FRONT_PATH` | お客様が見るストア一覧とストアページ：`/shop`、`/shop/{コード}` | `shop` |
| `MULTIVENDOR_ADMIN_PATH` | ベンダーの管理画面：`/vendor_admin`（ログインページと登録ページを含む） | `vendor_admin` |
| `PREFIX_QUICK_ORDER_VENDOR` | クイック注文ページの末尾：`/shop/{コード}/quick-order` | `quick-order` |
| `PREFIX_CATEGORY_VENDOR` | ストア独自のカテゴリページ | `category-vendor` |

変更する前に、次の 4 点に注意してください。

- **既存の URL と重複させないでください**：管理画面のプレフィックス（初期値 `gp247_admin`）、表内の他の変数、ストアフロントのページや商品の URL。重複すると、どちらかのページが開けなくなります。
- **`public/` 内に実在するフォルダー名は絶対に使わないでください** — 現在は `vendor`、`storage`、`GP247` です。実在するフォルダーはウェブサーバーが直接返すため、リクエストが S-Cart に届かず、設定に関係なく **403 Forbidden**（または白い画面）になります。ストアページの初期 URL が `vendor` **ではなく** `shop` なのは、このためです。症状を読み違えやすい点に注意してください。ストアページ `/{パス}/{コード}` は普通に動き、ストア一覧 `/{パス}` だけが表示されません。さらに SEO の言語プレフィックスをオンにしていると、エラー自体が隠れてしまいます。
- **古い URL は 404 になります。** すでに本番稼働していて Google にインデックスされているサイトでは、変更する前に古い URL から新しい URL への 301 リダイレクトを用意してください。
- 先頭と末尾に **`/` を付けずに** 書いてください。コマンドラインを使えないホスティングでは、`.env` を修正したあと、`gp247:cache-rebuild` コマンドの代わりに `bootstrap/cache/config.php` ファイル（あれば）を削除してください。

表示テキスト、メール内容、ストアページのデザイン、スタッフの権限を変更したい場合は、[第 3 部 — カスタマイズ](./multi-vendor-customize_ja.md) をご覧ください。

## 条件と制約（操作の前に確認）

**インストール時**
- **ウェブサイトに Multi-Store がインストールされている場合、プラグインはインストールを拒否します** — 2 つのプラグインは同じストアの仕組みを異なるモデルで使います。インストーラーはすぐに停止し、何も書き込みません。先に Multi-Store をアンインストールしてから、もう一度インストールしてください。
- **`gp247/shop` がインストールされている必要があります** — プラグインはショップの商品、カート、注文を利用します。
- **Pro 版には、有効になっている無料版が必要です** — Pro は拡張であり、置き換えではありません。無料版をアンインストールすると、Pro は動く土台を失います。
- **インストールしただけで有効にしていないと機能しません** — どちらの版も同じです。

**ストア / ベンダーアカウントの作成時**
- **ストアコードは一意で、最大 20 文字です** — コードは `/shop/{コード}` の URL に使われるため、重複するとシステムがどのストアを指すか判断できません。
- **1 つのベンダーアカウントは、ちょうど 1 つのストアに紐付きます** — 権限とデータ（注文、商品）はそのストアごとに分かれます。
- **アカウントがロックされているか、ストアが休業中の場合、ベンダー管理画面には入れません** — システムは「アカウントが有効化されていません」のページに移動します。管理者が再び有効にする必要があります。
- **無料版は 3 ストアまでです** — それ以上必要な場合は、Pro 版を追加でインストールしてください。

**プラグインのアンインストール時**
- **無料版をアンインストールすると、ベンダーアカウント、ストアのカテゴリ、出金台帳が削除されます**（S-Cart の商品と注文は残ります） — 残したいデータは、アンインストールの前にエクスポートしてください。
- **Pro 版をアンインストールしてもデータは失われません** — Pro が作成したデータは決して削除されず、再インストールすればすべて表示されます。

## トラブルシューティング
| 症状 | 対処方法 |
| --- | --- |
| **マーケットプレイス** メニューが表示されない | プラグインが（インストールだけでなく）**有効** になっているか確認します。`php artisan gp247:cache-rebuild` を実行します |
| *(Pro)* の項目をクリックしても説明ページが表示される | MultiVendorPro が **有効** になっているか確認し、`php artisan gp247:cache-rebuild` を実行します |
| インストール時に拡張機能が不足しているというエラーが出る | 先に無料プラグイン **MultiVendor** をインストールして有効にします |
| インストール時に競合のエラーが出る | ウェブサイトに Multi-Store がインストールされています。2 つのモデルは同時に使えないため、先に Multi-Store をアンインストールします |
| `/vendor_admin` で「アカウントが有効化されていません」と表示される | 管理者がベンダーアカウントのステータス **と** ストアのステータスの両方を有効にします |
| 画面にテキストではなく生のキーが表示される | **クイック設定** 画面を一度開き直す（プラグインが言語文字列を自動で再投入します）か、プラグインをオフにしてから再びオンにします |
| ベンダーの画面に Pro の項目が表示されない | アカウントとストアが有効な状態か、対応する機能がクイック設定でオンになっているかを確認します |
| 書き込み権限のエラー | `storage/` と `bootstrap/cache/` に書き込み権限を付与します |
| データベース接続のエラー | `.env` の `DB_*` の行を確認します |
| エラーの詳細を見たい | `storage/logs/laravel.log` を開きます |

## よくある質問（Q&A）
**Q1: サイトが S-Cart 2.x で動いている、または古い `sc:*` コマンドを使っています。インストールできますか？**

→ プラグインには `gp247/core` 3.0 が必要です。先に S-Cart を 3.x にアップグレードしてください。`gp247:*` コマンドが古い `sc:*` コマンドの代わりになります。

**Q2: ホスティングでコマンドを実行する権限がない場合はどうすればよいですか？**

→ ステップ 2 の方法 1 または方法 2（管理画面からのインストール）を使ってください。プラグインの動作に cron やキューは不要です。

**Q3: ベンダーはどこでログインし、マーケットプレイスの管理者はどこでログインしますか？**

→ ベンダーは `/vendor_admin` です。マーケットプレイスの管理者は、通常どおり S-Cart の管理画面です。2 つの画面は分かれており、アカウントを相互に使うことはできません。

**Q4: `/shop` の URL を別の名前に変えられますか？**

→ はい。`.env` に `MULTIVENDOR_FRONT_PATH` を設定し、`php artisan gp247:cache-rebuild` を実行します。`public/` 内のフォルダーと **重複しない** 名前を選んでください（`vendor`、`storage`、`GP247` は避けます）。上の 4 つの注意点もご覧ください。

**Q5: Pro をインストールする前に、無料版をアンインストールする必要がありますか？**

→ いいえ。Pro 版は無料版の **上に追加で** インストールし、無料版が有効になっている必要があります。

**Q6: 無料版を使っていた間に作成したデータは、Pro に移行しても残りますか？**

→ すべてそのまま残ります。ストア、ベンダーアカウント、商品、注文、出金台帳、そしてストア個別の手数料率も残ります。

**Q7: サンプルデータは削除できますか？**

→ **マーケットプレイス** で、ストア `vendor01`〜`vendor03` と対応するアカウントを手動で削除してください。本番サイトでサンプルデータ作成コマンドを実行しないでください。
